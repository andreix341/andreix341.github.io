Hollow Service

Type
DFIR
Difficulty
Medium
Focus
Windows intrusion reconstruction

Scenario

A Windows 10 workstation hosting an internal IIS application was flagged after unusual process creation activity originating from the IIS worker process. The endpoint was isolated, and a KAPE triage collection was taken before shutdown.

The investigation reconstructs the intrusion from IIS access, webshell upload and rename activity, PowerShell execution, token impersonation, UAC bypass activity, LSASS dumping, and local credential findings.

Task 1

What source IP address was used for the attacker's IIS requests?

IIS logs typically live under C:\inetpub\logs\LogFiles\W3SVC1\. Rather than reading every line manually, filter for suspicious behavior:

cs-method = POST
sc-status = 200, 201, 204
cs-uri-stem = upload endpoints
cs-uri-stem = .aspx, .ashx, .asmx
cs-uri-query containing cmd, exec, shell, upload, file
unusual User-Agent
large or unusual time-taken values

Useful strings:
cmd=
command=
exec
powershell
Invoke-
FromBase64String
whoami
net user
certutil
bitsadmin
upload
multipart/form-data
.aspx

Suspicious GET requests contain the parameter cmd=whoami.

Answer: 192.168.100.2

Task 3

What is the full filesystem path where the webshell was initially saved?

Run MFTECmd once to produce an MFT CSV. Open output\mft.csv in Calc, enable column filters, and filter ParentPath for inetpub\internalapp\uploads. Inspect the ASPX entries, particularly shell.aspx and status.aspx.

Answer: C:\inetpub\internalapp\uploads\shell.aspx

Task 4

The webshell was renamed after the initial upload. What name was it given?

Parse the collected USN journal with MFTECmd. Open output\usn.csv in Calc, filter Name for shell.aspx and status.aspx, and inspect rows containing RenameOldName or RenameNewName in UpdateReasons. Sort by UpdateSequenceNumber.

The matching file reference 314640-6 and parent entry 314622 confirm that both names belong to the same file. Returning to the IIS log shows the actor invoking uploads/shell.aspx at 10:43:52 UTC, followed by a successful invocation of uploads/status.aspx at 10:49:42 UTC.

Answer: status.aspx
