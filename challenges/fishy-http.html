Overview

A suspicious program is making HTTP requests to a web server. The supplied traffic capture and executable reveal a custom command-and-control channel. The flag is split into two parts: one is recovered from command output sent by the client, and the other is recovered by decoding commands sent from the server.

The PCAP contains traffic between 10.142.0.4 and 10.142.0.3:80. Only HTTP traffic is present. The client repeatedly:

  1. Sends GET /.
  2. Receives an HTML response.
  3. Decodes a hidden command.
  4. Executes it with cmd.exe.
  5. Sends command output using POST /submit_feedback.

This is a custom HTTP command-and-control channel.

Initial PCAP Analysis

capinfos sustraffic.pcapng
tshark -r sustraffic.pcapng -q -z io,phs -z conv,ip

The capture contains four POST requests to /submit_feedback. Their unusual sizes are:

  • 242 bytes
  • 20,783 bytes
  • 2,984 bytes
  • 2,817 bytes

The POST bodies contain random-looking words such as:

Invitation Fence Zombie vest book Horn Vegetable ...

Decoding the POST Channel

The executable contains the following encoding logic:

string text3 = Convert.ToBase64String(Encoding.UTF8.GetBytes(data));

Each Base64 character is followed by a random word beginning with that same character. Extracting the first character of every word reconstructs the Base64 string.

The decoded POST data reveals:

windows-instanc\pakcyberbot

Additional POSTs reveal Windows Server 2016 system information, the IP address 10.142.0.4, system memory and hardware details, directory listings, smphost.exe, and the second flag portion: [REDACTED].

Analyzing smphost.exe

Running the executable through ILSpy's command-line tool initially fails:

ilspycmd smphost.exe

The executable is a .NET single-file apphost, so the outer PE file does not contain the assembly metadata in the usual location. ILSpy can extract the bundled assembly directly:

ilspycmd smphost.exe --bundle-entry MyProject.dll

The decompiled code contains a tag-to-hex mapping:

{
    { "cite", "0" },
    { "h1", "1" },
    { "p", "2" },
    { "a", "3" },
    { "img", "4" },
    { "ul", "5" },
    { "ol", "6" },
    { "button", "7" },
    { "div", "8" },
    { "span", "9" },
    { "label", "a" },
    { "textarea", "b" },
    { "nav", "c" },
    { "b", "d" },
    { "i", "e" },
    { "blockquote", "f" }
}

The client parses HTML returned by the server. It ignores <li> tags and converts the remaining HTML tags into hexadecimal characters.

Decoding the Server Command

The HTML tag sequence decodes to commands such as:

whoami
systeminfo
dir && cd \Users\pakcyberbot\Documents\ && type HTB{[REDACTED]

The first flag portion is therefore: HTB{[REDACTED].

Final Flag

Combining both recovered portions produces a flag, but the flag value is intentionally obfuscated here:

HTB{[REDACTED]}

Conclusion

The challenge uses two custom covert channels:

  • HTML tag types encode commands from server to client.
  • Random words encode Base64 command output from client to server.

The executable is a .NET reverse-shell-style HTTP client that gathers command output and exfiltrates it through apparently harmless feedback forms.
