Focus
WordPress intrusion analysis

Scenario

A recently deployed internal server is believed to have been compromised. The server serves multiple internal purposes at Alliance Systems, so understanding the extent of the incident is critical. A triage image collected with the UAC tool is provided, although the incident occurred at least a day before the response team was informed and live artifacts may not be useful.

The image contains:

[root]
bodyfile
hash_executables
live_response
system
uac.log

Task 1

When did the attacker start the enumeration of the server?

[root]/var/log/apache2/access.log.1 contains the server requests. Requests from 192.168.72.131 use WPScan and are likely attacker activity:

192.168.72.131 - - [31/Jul/2026:09:09:22 +0000] "GET / HTTP/1.1" 200 12171 "http://192.168.72.164" "WPScan v3.8.28 (https://wpscan.com/wordpress-security-scanner)"

Answer: 2026-07-31 09:09:22

Task 2

The attacker performed a credential-stuffing attack. How many total attempts were made in total?

Multiple POST requests from the attacker IP target /wp-login.php through WPScan. Count them with:

grep 192.168.72.131 access.log.1 | grep -i wpscan | grep -c "POST /wp-login.php"

Answer: 45

Task 3

Which CVEs did the attacker chain together to gain command execution on the server?

The exploit is called wp2shell. The request POST /?rest_route=/batch/v1 HTTP/1.1 maps to CVE-2026-63030, while the chained SQL injection is CVE-2026-60137.

Answer: CVE-2026-60137, CVE-2026-63030

Task 4

When was the vulnerability exploited?

The first exploitation request was:

192.168.72.131 - - [31/Jul/2026:09:15:14 +0000] "POST /?rest_route=/batch/v1 HTTP/1.1" 207 9732 "-" "wp2shell"

Answer: 2026-07-31 09:15:14

Task 5

The exploit specifically adds spoofed timestamps during its exploitation of the backend. What is the spoofed timestamp value?

The value appears repeatedly as hexadecimal data inside the injected UNION ALL SELECT payload in [root]/var/www/html/wordpress/wp-content/debug.log.

Answer: 2020-01-01 00:00:00

Task 6

When did the attacker first gain OS-level RCE capability via the exploit?

The first successful command was id in this request:

192.168.72.131 - - [31/Jul/2026:09:16:08 +0000] "GET /wp-content/plugins/wp2shell_3bc0ab20/wp2shell_3bc0ab20.php?t=8070d9982f82daefc06aafc6b3cf7e73&c=id HTTP/1.1" 200 259 "-" "wp2shell"

Answer: 2026-07-31 09:16:08

Task 7

What is the full filesystem path of the web shell primarily used by the attacker?

URL-decoding the attacker’s command reveals the working directory and shell path:

192.168.72.131 - - [31/Jul/2026:09:16:32 +0000] "GET /wp-content/plugins/wp2shell_767ea7d9/wp2shell_767ea7d9.php?t=de336222b928e26a93e23138e5d6193b&c=cd+%2Fvar%2Fwww%2Fhtml%2Fwordpress%2Fwp-content%2Fplugins%2Fwp2shell_767ea7d9+2%3E%2Fdev%2Fnull%3B+uname+-a%3B+printf+%27__wp2shellcwd__%25s%27+%22%24%28pwd%29%22 HTTP/1.1" 200 410 "-" "wp2shell"

cd /var/www/html/wordpress/wp-content/plugins/wp2shell_767ea7d9 2>/dev/null; uname -a; printf '__wp2shellcwd__%s' "$(pwd)"

Answer: /var/www/html/wordpress/wp-content/plugins/wp2shell_767ea7d9/wp2shell_767ea7d9.php

Task 8

When did the attacker successfully log in to the machine with a privileged account due to password reuse across the blog and system login?

Filter auth.log for the attacker IP:

2026-07-31T09:23:10.784393+00:00 admsrv01 sshd[2130]: Accepted password for root from 192.168.72.131 port 50428 ssh2

Answer: 2026-07-31 09:23:10

Task 9

What is the full path of the file that the attacker added for persistence?

The persistence file is:

/root/.ssh/authorized_keys

It is located at [root]/root/.ssh/authorized_keys. The file contains an SSH key ending in root@kali, and bodyfile timestamps place its change during the incident. This allows passwordless root authentication.

Answer: /root/.ssh/authorized_keys

Task 10

What is the full path of the file that gave the attacker database credential access?

The root user's Bash history shows the attacker reading the WordPress configuration:

id
ls -la /var/www/html/
cat /var/www/html/wordpress/wp-config.php
mysqldump -u wpuser -p --all-databases > config.sql
mysqldump -u root -p --all-databases > config.sql

Answer: /var/www/html/wordpress/wp-config.php

Task 11

What is the full command that the attacker used to dump every database on the server?

After obtaining the database credentials, the attacker used mysqldump to export every database:

Answer: mysqldump -u root -p --all-databases > config.sql

Task 12

When was the database successfully dumped?

The dump was written to config.sql. Search the UAC artifacts:

grep -R 'config.sql' . 2>/dev/null
./[root]/root/.bash_history:mysqldump -u wpuser -p --all-databases > config.sql
./[root]/root/.bash_history:mysqldump -u root -p --all-databases > config.sql
./[root]/root/.bash_history:ls -la config.sql
./bodyfile/bodyfile.txt:0|/root/config.sql|524306|-rw-r--r--|0|0|1487161|1785490421|1785490120|1785490120|1785490043

The bodyfile entry contains:

1785490421 | 1785490120 | 1785490120 | 1785490043

atime: 09:33:41 UTC
mtime: 09:28:40 UTC
ctime: 09:28:40 UTC
crtime/birth time: 09:27:23 UTC

Answer: 2026-07-31 09:27:23

Task 13

What is the name of the WordPress administrator user that was created by exploiting the vulnerability to upload the web shell and used for the majority of their operation?

During the wp2shell phase, the attacker deletes the temporary administrator account:

192.168.72.131 - - [31/Jul/2026:09:18:38 +0000] "GET /wp-content/plugins/wp2shell_767ea7d9/wp2shell_767ea7d9.php?t=de336222b928e26a93e23138e5d6193b&delete_user=wp2_758d54eed8a9&reassign=1 HTTP/1.1" 200 189 "-" "wp2shell"

Answer: wp2_758d54eed8a9

Task 14

What is the username and hostname of the attacker's machine?

The username and hostname are visible in the SSH key stored in .ssh/authorized_keys.

Answer: root, kali
