Forensics

Focus
Userland rootkit analysis

Challenge Scenario

The SSH server is showing strange library-linking errors, and critical folders appear to be missing despite confirmation that they exist. The objective is to investigate the library-loading and filesystem anomalies, identify the hidden manipulation, and determine whether a userland rootkit is responsible.

Credentials: root:hackthebox

ssh root@<IP> -p <PORT>

Detecting Library Injection

Checking the dependencies of /bin/ls reveals an unexpected library:

ldd /bin/ls

The output includes:

/lib/x86_64-linux-gnu/libc.hook.so.6

This is not a normal system dependency. It is being injected into dynamically linked processes through the dynamic linker.

Process memory mappings confirm that the library is loaded into multiple processes, including PID 1:

grep -R 'libc.hook' /proc/*/maps 2>/dev/null

Inspection of the library reveals hooks for filesystem-related functions:

  • readdir
  • readdir64
  • fopen

It also contains references to:

  • ld.so.preload
  • pr3l04d

Together, these indicators point to a userland rootkit using LD_PRELOAD-style library injection to hide files and directories.

Rootkit Behavior

Normal commands fail to show certain files. The injected library intercepts directory and file operations, causing tools such as ls, find, and cat to hide rootkit-related paths.

The suspicious library is located at:

/lib/x86_64-linux-gnu/libc.hook.so.6

Disabling the Rootkit

Move the injected library out of the loader's search path:

mv /lib/x86_64-linux-gnu/libc.hook.so.6 /tmp/

Start a new shell or reconnect through SSH afterward. Newly launched processes will no longer load the malicious library.

Finding the Flag

With the rootkit disabled, filesystem enumeration works normally:

find / -name '*.txt' 2>/dev/null

The previously hidden flag file becomes visible and can be read normally.

Root Cause

The server was compromised with a userland rootkit implemented as a malicious shared library. The library was loaded into dynamically linked processes and hooked readdir, readdir64, and fopen to hide artifacts from standard tools.

The key indicators were:

  • Unexpected libc.hook.so.6 dependency in ldd
  • Library mapped into PID 1 and other processes
  • Suspicious filesystem-related exported symbols
  • References to ld.so.preload and pr3l04d
  • Missing files becoming visible after moving the library away
